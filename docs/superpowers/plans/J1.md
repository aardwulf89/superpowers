# J1: A split into plans needs a reason Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers-extended-cc:subagent-driven-development (recommended) or superpowers-extended-cc:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One identical rule block governs every place that splits work into plans.

**Architecture:** The block sits between `<!-- split-rule -->` and `<!-- /split-rule -->` markers, once per file, in five files. Each place keeps one or two lines of its own around it. A shell test extracts every copy and fails if any differs, and pins the removed and added lines.

**Tech Stack:** Markdown skill text, bash tests in the style of `tests/chaining-plans/test-resume-text.sh` (`has` / `lacks` with `grep -qF`).

**Spec:** `docs/superpowers/specs/J.md`

## Global Constraints

- The block is exactly the text below, byte for byte, at column 0, outside any list item, in every copy. Copy it from here; never retype it.

```markdown
<!-- split-rule -->
**Splitting into plans.** Each plan costs a design, reviews, a branch
and a merge. Split only where:

1. neither part needs the other's code; or
2. a later part needs facts only an earlier part's running code shows.
   Research that needs no code belongs in the brainstorm.

A split for size, or to merge a part first, is your human partner's
call: propose it, never rule it.

Never reasons: a seam or section in a design, a precedent, a topic, a
part that only researches or wraps up.

A part waits on another only when it needs that part's code, never for
work order.
<!-- /split-rule -->
```

- One copy per file: `skills/writing-plans/SKILL.md`, `skills/brainstorming/SKILL.md`, `skills/chaining-plans/references/create.md`, `skills/chaining-plans/references/resume.md`, `skills/chaining-plans/references/close.md`.
- No place points to another skill for the rule.
- `skills/brainstorming/SKILL.md` stays under 20000 bytes (`tests/skill-size/test-skill-size.sh`; `writing-plans`, `executing-plans` and `subagent-driven-development` already fail it before this plan).

**User decisions (already made):**
- "The subsystem split is actually sound": splits by separate code stay.
- The agent may propose a size split; only the partner approves it.
- The same block, word for word, at every split point, with no cross-skill pointers.
- The block's wording is final (spec J, "The rule").

## Review Focus

- A copy that differs by whitespace or wrapping from the others: the identity test must catch it (it compares bytes).
- A copy inside a list item, indented: it renders as part of the list and breaks the identity check. Every copy is at column 0.
- A marker typo (`<!-- split rule -->`): the test must fail on a count other than 5, not skip the file.
- Old split wording left beside the new block (`one per subsystem`, `A further split from the Scope Check`): the `lacks` pins catch it.
- The Resume size proposal stalling an unattended session: it is a `Partner item:` line in "Unfinished", not a stop.
