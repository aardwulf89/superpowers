# K1: The record keeps what the brainstorm learned Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers-extended-cc:subagent-driven-development (recommended) or superpowers-extended-cc:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give an effort record a top-level `learned` list that Create seeds from the brainstorm, every Design stage reads, and every close keeps true, read and written only through `record.py`.

**Architecture:** `record.py` gains `get-effort` and `set-effort-key`, sharing the append/replace/edit logic with `set-closing-key`; `new-record` accepts the optional key. The chaining-plans reference files (record, create, resume, close) and `SKILL.md` describe when it is seeded, read and pruned, pinned by a new text test.

**Tech Stack:** Python 3 (stdlib only), bash tests with jq.

**Spec:** `docs/superpowers/specs/K.md`

## Global Constraints

- The key is top-level `learned`, beside `umbrella` and `base`: `null` or a list of strings. A record without the key reads exactly as `null`.
- Phases keep exactly their nine keys. `PHASE_KEYS` and `CLOSING_KEYS` do not change.
- Refusals print `record <subcommand>: <reason>` on stderr, exit 1, and write nothing; usage mistakes exit 2 (argparse). Writes go through `write_record`.
- No change to `skills/brainstorming/`.
- Skill prose stays in the existing voice ("your human partner", short imperative lines). Do not reword text the change does not need.

**User decisions (already made):**
- "A": if Create runs in a session that holds no brainstorm, it seeds nothing (`[]`) and says so in the hand-over; brainstorming is not changed.
- "1": the knowledge lives in a top-level `learned` list in the record, not in a notes file or a phase 0.
- "implementation gets a final pass for STE and tightening/token optimization of all writes": Task K1.3.

## Review Focus

1. A record written before this change (no `learned` key): `get-effort` prints `null`, `set-effort-key … append` starts from empty, `edit` refuses because the line is not there. Tests in K1.1.
2. `new-record` given `learned` as a string, or as a list holding a non-string: refused, nothing written. Test in K1.1.
3. `set-effort-key` with a key other than `learned` (`umbrella`, `base`, `phases`): refused, record unchanged. Test in K1.1.
4. `set-effort-key … replace` or `append` with a value that is not a list of strings: refused. Test in K1.1.
5. A write to `learned` leaves `umbrella`, `base` and `phases` byte-for-byte as they were and leaves no `.tmp`. Test in K1.1.

### Task K1.1: record.py reads and writes the effort's `learned`

**Goal:** `new-record` accepts an optional top-level `learned`; new `get-effort` and `set-effort-key` subcommands read and write it.

**Files:**
- Modify: `skills/chaining-plans/scripts/record.py`
- Test: `tests/chaining-plans/test-record-commands.sh`

**Acceptance Criteria:**
- [ ] `record.py get-effort REC learned` prints the key as compact JSON, `null` when absent.
- [ ] `record.py set-effort-key REC learned {append|replace|edit} (--value|--value-file)` writes it with the same semantics as `set-closing-key` (append onto null = onto `[]`; edit by exact line).
- [ ] Both refuse any key but `learned`; `set-effort-key` refuses a non-list or a list with a non-string for append/replace.
- [ ] `new-record` accepts `learned` absent, `null`, or a list of strings; refuses any other value.
- [ ] Every Review Focus line 1–5 has a passing test.

**Verify:** `bash tests/chaining-plans/test-record-commands.sh` → `All record command tests passed`

**Steps:**

- [ ] **Step 1: Write the failing tests** — append a `# effort learned` block before the final failures check in `tests/chaining-plans/test-record-commands.sh`, using the file's own `check`, `refuses`, `phase`, `write_rec` helpers:

```bash
# effort learned
EL="$TMP/effort-learned.json"
write_rec "$EL" "$(phase K1 known open '[]')"   # an old record: no learned key
check "get-effort prints null for an old record" 'null' "$(record get-effort "$EL" learned)"
refuses "edit refuses a line of an absent learned" "$EL" record set-effort-key "$EL" learned edit --value '{"drop":["x"]}'
before="$(jq -c '{umbrella,base,phases}' "$EL")"
record set-effort-key "$EL" learned append --value '["a","b"]'
check "append onto an absent learned" '["a","b"]' "$(record get-effort "$EL" learned)"
check "a learned write keeps umbrella, base and phases" "$before" "$(jq -c '{umbrella,base,phases}' "$EL")"
if [[ ! -e "$EL.tmp" ]]; then pass "set-effort-key leaves no .tmp file"; else fail "set-effort-key leaves no .tmp file"; fi
record set-effort-key "$EL" learned edit --value '{"edit":[["a","A"]],"drop":["b"]}'
check "edit changes and drops lines" '["A"]' "$(record get-effort "$EL" learned)"
record set-effort-key "$EL" learned replace --value '["z"]'
check "replace sets the list" '["z"]' "$(record get-effort "$EL" learned)"
refuses "set-effort-key refuses umbrella" "$EL" record set-effort-key "$EL" umbrella replace --value '["x"]'
refuses "set-effort-key refuses phases" "$EL" record set-effort-key "$EL" phases replace --value '[]'
refuses "get-effort refuses base" "$EL" record get-effort "$EL" base
refuses "set-effort-key refuses a non-list" "$EL" record set-effort-key "$EL" learned replace --value '"x"'
refuses "set-effort-key refuses a non-string line" "$EL" record set-effort-key "$EL" learned append --value '[1]'
refuses "get-effort refuses a missing record" "$TMP/none/effort.json" record get-effort "$TMP/none/effort.json" learned
N3="$TMP/new/e3/effort.json"
record new-record "$N3" --value "$(jq -c '.learned = ["seed"]' <<<"$good")"
check "new-record keeps a seeded learned" '["seed"]' "$(record get-effort "$N3" learned)"
N4="$TMP/new/e4/effort.json"
record new-record "$N4" --value "$(jq -c '.learned = null' <<<"$good")"
check "new-record accepts a null learned" 'null' "$(record get-effort "$N4" learned)"
N5="$TMP/new/e5/effort.json"
refuses "new-record refuses a string learned" "$N5" record new-record "$N5" --value "$(jq -c '.learned = "x"' <<<"$good")"
refuses "new-record refuses a non-string line" "$N5" record new-record "$N5" --value "$(jq -c '.learned = [1]' <<<"$good")"
```

- [ ] **Step 2: Run to verify it fails**

Run: `bash tests/chaining-plans/test-record-commands.sh`
Expected: FAIL lines for `get-effort` / `set-effort-key` (invalid choice, usage exit 2).

- [ ] **Step 3: Implement in `skills/chaining-plans/scripts/record.py`**

- `EFFORT_KEYS = ("learned",)` next to `CLOSING_KEYS`.
- `def string_list(value: Any) -> bool` — a list whose items are all `str`.
- `def apply_mode(current: list, value: Any, mode: str, key: str) -> list` — the append/replace/edit logic now inline in `cmd_set_closing_key` (non-list refused for append/replace; `edit_lines` for edit). `cmd_set_closing_key` calls it; its behavior and messages do not change.
- `def cmd_get_effort(args) -> int` — refuses a key not in `EFFORT_KEYS` (`'<key>' is not an effort key (learned)`); prints `dumps(record.get(key))`.
- `def cmd_set_effort_key(args) -> int` — refuses a key not in `EFFORT_KEYS`; current = `record.get(key) or []` (refuse if not a list); for append/replace also refuse unless `string_list(value)`; for edit, refuse unless the result is a string list (edit_lines guarantees it); sets `record[key]`, `write_record`.
- `cmd_new_record`: also refuse when `"learned" in value` and it is neither `None` nor a `string_list`.
- Parsers: `get-effort` (rec, key), help `"print one effort-level key (learned) as JSON"`; `set-effort-key` (rec, key, mode choices replace/append/edit, value), help `"set or extend one effort-level key (learned)"`.

Expected: `All record command tests passed`
