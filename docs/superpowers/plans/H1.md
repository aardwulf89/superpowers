# H1: The plan carries the dependencies Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers-extended-cc:subagent-driven-development (recommended) or superpowers-extended-cc:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** writing-plans records only hard dependencies in `blockedBy`, and subagent-driven-development dispatches every task whose `blockedBy` tasks are complete, each implementer in its own worktree, with no run-time dependency ruling.

**Architecture:** Text changes only, in two skills, plus the text tests that pin them. Task H1.1 changes writing-plans. Task H1.2 changes subagent-driven-development and its references. Neither task needs the other's commits.

**Tech Stack:** Markdown skill files; bash text tests (`has` / `lacks` helpers).

**Spec:** docs/superpowers/specs/H.md

## Global Constraints

- Replace text exactly as each step gives it. Each step names the old text to find and the new text to put in its place.
- The hard-dependency definition is fixed, word for word: "Task B waits for task A only when B cannot be completed in a tree without A's commits: B's steps, tests or Verify step need code, files or behaviour that A adds, changes or removes. Plan order, a shared file, and text that only repeats what the plan already fixes are never reasons. A task with no such need has no `blockedBy`."
- `tests/skill-size/test-skill-size.sh` already fails for `executing-plans`, `subagent-driven-development` and `writing-plans` (each SKILL.md is over 20000 bytes) before this plan. Do not try to fix it. Do not move content to make it pass.
- No change to `references/resuming.md`, `references/handling-reports.md`, `executing-plans`, `chaining-plans`, or any hook.

**User decisions (already made):**
- "The plan carries the dependencies": writing-plans sets `blockedBy` only for hard dependencies; plan order alone is never one.
- "One way to dispatch": every implementer works in its own nested worktree; the controller dispatches every task whose `blockedBy` tasks are complete.
- "No run-time dependency ruling, and no script."
- The hard-dependency definition in Global Constraints, approved as worded.
