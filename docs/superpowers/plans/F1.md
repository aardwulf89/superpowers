# F1: Parallel dispatch in subagent-driven development Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers-extended-cc:subagent-driven-development (recommended) or superpowers-extended-cc:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Subagent-driven development runs a plan's independent tasks in parallel, each writer in its own nested worktree, by rules only.

**Architecture:** A new reference file holds the rules. `SKILL.md` keeps a one-sentence trigger at the dispatch step and phrase changes in §Bounded Parallel Dispatch. The pre-flight scan gains the dependency ruling, and resuming gains a pointer. Text tests pin the load-bearing phrases.

**Tech Stack:** Markdown skill text; bash text tests in the style of `tests/reference-ids/test-reference-ids.sh`.

**Spec:** `docs/superpowers/specs/F.md`

## Global Constraints

- Change only the files this plan names. Never touch `skills/writing-plans/`,
  `skills/chaining-plans/`, `references/final-review.md`,
  `references/deferred-findings.md`, the per-task loop's ledger forms, or
  any hook.
- In §Bounded Parallel Dispatch of `SKILL.md` (pcvelz's section), change
  only the phrases spec F names, plus the one quote of the old ban sentence
  in its first paragraph (it quotes a sentence this plan replaces). Every
  other line of that section stays byte-identical.
- No scripts, hooks, caps or schedulers. The design is rules only.
- Every git command the new file gives is one plain command per call
  (the harness refuses compound git commands in an isolated worktree).
- Voice: the fork's skill text (short sentences, one instruction per
  sentence, "your human partner", as in commit 672152f).
- `tests/skill-size/test-skill-size.sh` fails on `main` before this plan
  (SDD `SKILL.md` is over its limit). It is not a gate for this plan; do
  not cut content to satisfy it.

**User decisions (already made):**
- Goal: phases finish sooner.
- Parallel dispatch is automatic within the plan; anything beyond the plan
  needs the partner's approval, with counts.
- A single controller; rules only, no machinery.
- writing-plans is not changed; dependencies come from the pre-flight scan.
- The final whole-branch review, its fix wave, its re-review and the
  deferred-findings round are not changed.
- pcvelz's test changes "in the other's `blockedBy` chain" to "in the
  pre-flight's dependency ruling".
- In an unattended run, the controller never stops to ask about parallel
  work beyond the plan: it runs the plan as written and reports the
  proposal under "Unfinished".

## Review Focus

1. A controller that reads only the dispatch step: the trigger sentence
   there must send it to the reference file whenever two or more tasks are
   ready (Task F1.2 pins the sentence).
2. A contradiction between §Bounded Parallel Dispatch and the new file
   (for example the old "sequential remains the default" line kept beside
   "automatic"): Task F1.2's test asserts the old lines are gone.
3. A command in the new file that the harness refuses inside an isolated
   worktree (a compound git command, `cd … &&`): Task F1.1's review checks
   each command is one plain command.
4. Text that lets the phase worktree be written while a nested worktree
   exists, or a reviewer read the phase worktree: Task F1.1 pins "While any
   nested worktree exists".
5. Machinery or a cap creeping back into the text: Task F1.1's test asserts
   the file names no writer cap and no script of its own.
