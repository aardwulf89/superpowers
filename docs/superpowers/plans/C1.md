# C1: chaining-plans carries only what is worth carrying Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Seal the two channels of `chaining-plans`. `learned` is curated as a whole at each close. A partner item is held in one marked line until the partner gives it a disposition. An effort is closed out only when every item has one. Carried items reach the next Create.

**Architecture:** `record.py` learns to read partner-item lines and the effort-level `"marked"` flag. `pick` gains the values `items` and `unmarked`, `open-efforts` lists an effort whose items are open, and a new `carried` lists the items carried past done efforts. The references change in prose. `resume.md` owns the end round and the last message, `create.md` owns `"marked"` and the carried items, and `close.md` owns the sorting of items, the check before writing and the revise step. Two new headless integration tests are the RED/GREEN pressure tests of the prose.

**Tech Stack:** Python 3 (standard library), bash test scripts, jq in tests only, headless `claude -p` integration tests.

**Spec:** `docs/superpowers/specs/C.md`

## Global Constraints

- The script uses only the Python standard library and runs on Python 3.8 or later. It runs git read-only, and the only file it writes is a record, through `<rec>.tmp` and an atomic rename.
- Every invocation the references show is one plain command, `python3 <skill base>/scripts/record.py <subcommand> <args>`, with literal arguments.
- A refused command prints `record <subcommand>: <reason>` on stderr, exits 1, and changes nothing.
- The record's shape is unchanged, except for one effort-level key, `"marked": true`, written by Create.
- A partner-item line is an element of a phase's `closing.unfinished` that starts with the exact prefix `Partner item: `. Its disposition is a suffix at the very end of the line, one of `[settled: <phase id>]`, `[dropped]`, `[carried]` or `[adopted by <phase id>]`. A line with none of them is open.
- The skill writes no project doc. Only the partner gives a disposition.
- `skills/chaining-plans/SKILL.md` stays under 20,000 bytes (`tests/skill-size/test-skill-size.sh`).
- Commit subjects: `feat(C1.<n>): …`, `docs(C1.<n>): …` or `test(C1.<n>): …`, each ending with the session's attribution trailer.

## Review Focus

- A partner item whose text holds a bracket mid-line, such as `Partner item: keep "[carried]" as the word? Default: as is.`, is open. Only a suffix at the end of the line counts. (C1.1)
- A phase with `closing: null`, or with an `unfinished` that is missing or null, adds no item and does not crash `pick`, `open-efforts` or `carried`. (C1.1)
- An open partner item in a `dropped` phase still makes `pick` print `items`. (C1.1)
- `carried` skips an unreadable record with a note on stderr and lists the rest, as `open-efforts` does. (C1.1)
- A session cleared after the end round was shown, before the partner answered: the next Resume shows the end round again and never says "closed out". The agent never gives a disposition itself, even when the prompt asks it to wrap up quickly. (C1.2, in its integration test)

It finds the directory as `open-efforts` does, and skips an unreadable record with a note on stderr.
