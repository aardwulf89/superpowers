# D1: One task schema for chained and executor runs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every harness task that chaining-plans, subagent-driven-development and executing-plans make follows the `<id>: <name>` schema, is blocked by what it waits on, and moves through its states by a stated rule.

**Architecture:** Skill text only. The executors' Setup paragraph (one copy in each SKILL.md) carries the executor's task rules. Resume §3, §6 and the Plan stage, Create, and Close each get the rules for their part. One new static test pins the wording in all five files; the reference-ids test drops the old title forms.

**Tech Stack:** Markdown skill files, bash test scripts (`has`/`lacks` helpers over `grep -F`).

**Spec:** `docs/superpowers/specs/D.md`

## Global Constraints

- Title schema: `<id>: <name>`. No "Task" word in a task title. Plan headings (`### Task K3.4: …`) and ledger lines (`Task K3.4: complete`) do not change.
- Step names stay fixed words, so titles match exactly: `Intent round`, `Design`, `Plan`, `Build`, `Finish`, `Close`, `Missed close`, `Missed git ops`, `Final whole-branch review`, `Deferred-findings round`, and Create's five step headings word for word (`Draft the phases`, `Find the open intent questions`, `Run one sitting`, `Write it down`, `Hand over`).
- New text is in the STE-leaning style of the `7.0.2+aardwulf.8` paragraph in `resume.md` §6: short imperative sentences, one action each, "Do not" in place of "Never", conditions as lists.
- Name the Claude Code tools as the existing text does: `TaskCreate`, `TaskUpdate`, and their fields `blockedBy` and `activeForm`.
- The 20000-byte SKILL.md limit is overridden for this work: `tests/skill-size/test-skill-size.sh` already fails for both executors before D1 and may still fail after it. Do not move content to references to satisfy it.
- No version bump, no push: those are a separate step after review.
- Commit subjects: `fix(D1.<n>): …` or `test(D1.<n>): …`.

## Review Focus

- An executor run inside a chain must not make a second `<plan id>: Finish` when Resume made one already, and it must still add its last task as that task's blocker. (D1.1)
- An executor run on its own, with no chain, must still get a `<plan id>: Finish` task. (D1.1)
- A Scope Check split must retitle only stage tasks that are not completed; `K3: Design`, done, keeps its title. (D1.2)
- A `cut-off` resume makes no task for a plan task whose ledger has a completion line, and no Design or Plan stage task. (D1.1, D1.2)
- A plan without an id (`<plan id>` empty) keeps working: its titles start bare, as the executors' Ids paragraph already says for every line that would start with `<plan id>:`. (D1.1)
