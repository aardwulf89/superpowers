# B1: chaining-plans under native worktrees Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make a chained effort run end to end through Claude Code's `EnterWorktree`, by replacing `record.md`'s inline shell blocks with one Python script run by its path, and by fixing the worktree wording in chaining-plans and finishing.

**Architecture:** `skills/chaining-plans/scripts/record.py` is a stdlib-only CLI with one subcommand per record operation. The worktree guard accepts it because each call is one plain command. The references call it instead of composing shell and jq. Separately, `finishing-a-development-branch` leaves a confined worktree before its merge and cleans it up after. chaining-plans enters and leaves worktrees with the harness tools, and records whatever branch name the tool gives.

**Tech Stack:** Python 3 (standard library only), bash test scripts, git.

**Spec:** `docs/superpowers/specs/B.md`

## Global Constraints

- The script uses only the Python standard library and runs on Python 3.8 or later. The skill no longer needs `jq` at run time; tests may still use it.
- The script runs git read-only, and the only file it writes is the record (`effort.json`), through `<rec>.tmp` and an atomic rename.
- Every invocation the references show is one plain command: `python3 <skill base>/scripts/record.py <subcommand> <args>`, with literal arguments. No variable assignments, `&&`, `;`, `$(…)` or heredocs.
- A refused command prints `record <subcommand>: <reason>` on stderr, exits 1, and changes nothing. A usage error exits 2 (argparse).
- The record's shape, its ten phase keys and its phase states are unchanged.
- Never `--force` a worktree removal.
- Commit subjects: `feat(B1.<n>): …`, `docs(B1.<n>): …`, or `test(B1.<n>): …`.

## Review Focus

- An unknown phase id passed to `phase-state` or `get` is refused (exit 1). Today's block silently reads it as `not-started`. (B1.1)
- A value file holding apostrophes, double quotes and non-ASCII text (`it's "done" — café`) round-trips byte-for-byte into the record. (B1.2)
- A missing or malformed record is refused by every write, and no record or `.tmp` is created. (B1.2)
- Run from a subdirectory of a linked worktree, `chain-dir` prints the main checkout's chain directory. (B1.1)
- A write that cannot complete (the record's directory is read-only) leaves the old record intact and no `.tmp`. (B1.2)

### Task B1.2: The record script, write side

**Files:**
- Modify: `skills/chaining-plans/scripts/record.py`
- Modify: `tests/chaining-plans/test-record-commands.sh`

**Interfaces:**
- Consumes: `load_record`, `phase_of`, `Refused`, `main` from Task B1.1.
- Produces: `read_value(args) -> Any` (exactly one of `--value`, `--value-file`, enforced by an argparse mutually exclusive required group; refuses JSON that does not parse, and an unreadable file), and `write_record(path: str, record: dict) -> None` (writes `json.dumps(record, indent=2, ensure_ascii=False) + "\n"` to `<path>.tmp`, then `os.replace`; on any error removes the `.tmp` and raises `Refused`).
- `new-record`, `set` and `set-phases` keep their blocks' checks from `record.md` (ten keys exactly, distinct ids, `umbrella` and `base` strings, an existing `rec` refused by `new-record`, a phase id with that field for `set`). `new-record` creates the record's parent directories.
- `set-closing-key REC ID KEY MODE`: KEY is one of `rulings`, `unfinished`, `learned`, `replan`, and the value must be a JSON list. A null `closing` starts as `{"rulings": [], "unfinished": [], "learned": null, "replan": null}`. `replace` sets the key to the list. `append` extends the key's list, a null key counting as `[]`, and is refused for `replan`. Every other key is kept as read.

Convert the `set`, `set-phases` and `new-record` checks to `record set "$S" K2 branch --value '"K2"'` and so on. Change `refuses` to take a command line: `refuses NAME FILE record <args…>`, which passes when the command exits non-zero, FILE is unchanged, and no `FILE.tmp` exists. Add:

```bash

  "$(jq -c '.phases[0].closing' "$S")"
record set-closing-key "$S" K1 rulings append --value '["b"]'
check "append extends" '["it'\''s \"done\" — café","b"]' "$(jq -c '.phases[0].closing.rulings' "$S")"

record set-closing-key "$S" K1 replan replace --value '[]'

refuses "set-closing-key refuses a value that is not a list" "$S" record set-closing-key "$S" K1 learned replace --value 'null'
refuses "set-closing-key refuses replan back to null" "$S" record set-closing-key "$S" K1 replan replace --value 'null'
refuses "set-closing-key refuses an unknown key" "$S" record set-closing-key "$S" K1 notes replace --value '[]'
refuses "set-closing-key refuses an unknown id" "$S" record set-closing-key "$S" K9 rulings append --value '[]'

refuses "set refuses a malformed record" "$BAD" record set "$BAD" K1 branch --value '"x"'   # BAD holds '{'

st=0; record set "$S" K1 branch --value '"x"' --value-file "$TMP/v.json" 2>/dev/null || st=$?
check "set refuses both value forms (usage)" 2 "$st"
check "set --value-file round-trips text" '["it'\''s \"done\" — café"]' \
```
