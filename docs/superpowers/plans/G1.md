# G1: chaining-plans record writes and reads that spend less Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers-extended-cc:subagent-driven-development (recommended) or superpowers-extended-cc:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cut three costs that effort D of Lairage measured. Closes rewrite whole `learned`/`unfinished` lists to change one line (~27k output tok). `learned` repeats project instructions and bookkeeping (~25% of it). Reads of `closing` pull in `rulings` that nothing uses (~25k input tok).

**Architecture:** `record.py` gets two things. `get REC ID closing.<key>` prints one closing key. `set-closing-key … edit` drops or changes lines by their exact text, and refuses the write if a line is not there. The references then use them. Close step 1 also gets two rules on what `learned` leaves out.

**Tech Stack:** Python 3.8+ standard library (`record.py`), bash test scripts, Markdown skill references.

**Spec:** none. The evidence is the analysis in `~/tmp/chain-budget/report.md` (effort D of Lairage), and the owner's decisions below.

## Global Constraints

- `record.py` stays on the standard library and Python 3.8+. A refused command prints `record <subcommand>: <reason>` on stderr, exits 1 and writes nothing. A usage error exits 2.
- The existing `replace` and `append` modes and `get REC ID [FIELD]` keep their behavior. Every current test still passes.
- Keep the references' voice: short sentences, "your human partner", and full ids. Do not touch the Red Flags table.
- Close step 1's own-phase check of the build's `rulings` keeps reading `closing.rulings`. No step loses a read that it needs.

**User decisions (already made):**
- "edit mode: drop/change lines by exact text, refuse if not found", used in close 1a, close 2 and create 5. Resume's suffix writes are the same pattern, so they use it too.
- `replace` stays for writes that change most of a list: the first write of `learned`, and the sort of `unfinished`.
- Close step 1 leaves out of `learned` what AGENTS.md, a project skill or a lint gate already holds, and bookkeeping lines.
- Reads use subfields (`closing.learned`, `closing.unfinished`), except close step 1's own-phase `rulings` check.
- Implement in this session, with native tasks. Do not run `tests/claude-code/` (live sessions).

## Review Focus

- A line that appears twice in a list: `edit` takes one occurrence per listed line, the first. Test: drop "b" from `["a","b","c","b"]` gives `["a","c","b"]`.
- A stale or misremembered line: `edit` refuses the whole write, and the record does not change. Test: drop a missing line → exit 1, file unchanged.
- `edit` on a null key (no closing yet): every listed line is missing, so it refuses. Test in G1.2.
- `get … closing.<key>` on a null `closing` prints `null`, not an error. Resume and discard read it before a close has run. Test in G1.1.
- Text with quotes and non-ASCII characters keeps its exact bytes through `edit`. Test: edit the `café` line.

### Task G1.2: `set-closing-key` edits lines by their text

**Goal:** `record.py set-closing-key REC ID KEY edit` drops or changes lines of a list key by their exact text, and refuses the whole write if a line is not there.

**Files:**
- Modify: `skills/chaining-plans/scripts/record.py` (`cmd_set_closing_key`, the `mode` choices, the docstring)
- Modify: `skills/chaining-plans/references/record.md` (`### set-closing-key`)
- Test: `tests/chaining-plans/test-record-commands.sh`

**Acceptance Criteria:**
- [ ] The value is a JSON object with `drop` (a list of strings) and/or `edit` (a list of `[old, new]` string pairs). It holds no other key, and at least one line.
- [ ] `edit` pairs apply first, then `drop`. Each listed line matches the first whole element equal to it that is still unmatched. Order is kept, and other keys are kept.
- [ ] It refuses, and writes nothing, for:
  - a line that is not there: `'<line, first 60 chars>' is not a line of <key>`;
  - KEY `replan`: `replan is written whole, with replace`;
  - a value that is not such an object.
- [ ] `replace` and `append` are unchanged.
- [ ] `record.md` § set-closing-key documents `edit` and when to use it: a few lines, against a fresh `get`.

**Verify:** `bash tests/chaining-plans/test-record-commands.sh` → `All record command tests passed` with no `[FAIL]`

**Steps:**

- [ ] **Step 1: Write the failing tests** after the set-closing-key refusals. Use the file's `refuses NAME FILE cmd…` helper, which checks exit 1 and an unchanged file:
  ```bash
  record set-closing-key "$S" K1 learned replace --value '["a","b","c","b"]'
  record set-closing-key "$S" K1 learned edit --value '{"drop":["b"]}'
  check "edit drops the first equal line" '["a","c","b"]' "$(jq -c '.phases[0].closing.learned' "$S")"
  record set-closing-key "$S" K1 learned edit --value '{"edit":[["c","C"]],"drop":["a"]}'
  check "edit changes in place, then drops" '["C","b"]' "$(jq -c '.phases[0].closing.learned' "$S")"
  printf '%s' '{"edit":[["it'\''s \"done\" — café","café ✓"]]}' > "$TMP/e.json"
  record set-closing-key "$S" K1 rulings edit --value-file "$TMP/e.json"
  check "edit keeps exact bytes" '["café ✓","b"]' "$(jq -c '.phases[0].closing.rulings' "$S")"
  check "edit keeps the other keys" '["C","b"] []' "$(jq -c '.phases[0].closing.learned, .phases[0].closing.replan' "$S" | paste -sd' ')"
  refuses "edit refuses a line that is not there" "$S" record set-closing-key "$S" K1 learned edit --value '{"drop":["zz"]}'
  refuses "edit refuses replan" "$S" record set-closing-key "$S" K1 replan edit --value '{"drop":["x"]}'
  refuses "edit refuses a list value" "$S" record set-closing-key "$S" K1 learned edit --value '["b"]'
  refuses "edit refuses an empty edit" "$S" record set-closing-key "$S" K1 learned edit --value '{}'
  refuses "edit refuses an unknown key" "$S" record set-closing-key "$S" K1 learned edit --value '{"remove":["b"]}'
  refuses "edit refuses a pair that is not two strings" "$S" record set-closing-key "$S" K1 learned edit --value '{"edit":[["b"]]}'
  refuses "edit refuses a line of a null key" "$S" record set-closing-key "$S" K2 learned edit --value '{"drop":["x"]}'
  ```
  The last check needs K2's `closing` to be null at that point. If an earlier check set it, use another phase whose `closing` is null.
- [ ] **Step 2: Run** the Verify command. Expected: the new checks FAIL (`invalid choice: 'edit'`).
- [ ] **Step 3: Implement.** Add `edit` to `mode` choices. In `cmd_set_closing_key`, put the `edit` branch before the list check, because its value is an object. Refuse `replan`. Validate the object's shape as in the criteria. Copy the current list (null is `[]`). Apply each `[old, new]` pair, then each `drop`, to the first equal element still unmatched. Refuse if any line is missing. Write once, at the end.
  - Extract `edit_lines(current: list, value: Any, key: str) -> list`, which returns the new list or raises `Refused`.
  - Docstring: `set-closing-key REC ID KEY {replace,append,edit} (--value JSON | --value-file PATH)`.
- [ ] **Step 4: Document** in `record.md` § set-closing-key: the `edit` mode, its value shape with one example, the order (edit pairs first, then drops, first equal line each), and the refusals. Say when to use it: to drop, correct or extend a few lines, each copied exactly from a fresh `get`. A misremembered line then fails, and nothing changes. `replace` stays for a list that changes in most of its lines.
- [ ] **Step 5: Run** the Verify command. Expected: PASS.
- [ ] **Step 6: Commit** `git commit -m "feat(G1.2): set-closing-key edits lines by their text"`
